## Зачем

Claude Code теряет контекст. Планы исчезают после сжатия. Задачи забываются между сессиями. Изменения идут прямо в main без трассировки.

Claude Protocol решает это тремя вещами:

- **Beads** — персистентное отслеживание задач. Одна задача = один worktree = один PR. Переживает перезапуски и сжатие контекста.
- **Хуки** — enforcement, а не инструкции. Редактирование на main заблокировано. Завершение без чеклиста заблокировано. `git --no-verify` заблокирован.
- **bd prime** — хук SessionStart загружает недавние beads, так что состояние переживает потерю контекста.

Ограничения вместо инструкций. Что заблокировано — нельзя проигнорировать.

## Происхождение

Проект начался как форк [The Claude Protocol](https://github.com/AvivK5498/The-Claude-Protocol) Авива Каплана. Автор оригинала, похоже, прекратил разработку — PR не рассматриваются, а базовые инструменты (beads CLI, API хуков Claude Code) значительно изменились.

v3 — это переписывание с нуля. Другая архитектура, другая философия. Подробности: [decisions-ru.md](docs/decisions-ru.md).

## Что изменилось в v3

### Не выпущено

- **Установка плагином** — репозиторий стал ещё и маркетплейсом Claude Code.
  Плагин несёт хуки, агентов и навык и сам их обновляет; `/claude-protocol:init`
  раскладывает половину, которую плагин нести не умеет (beads, правила,
  `CLAUDE.md`), и снимает прежнюю установку через `npx`, чтобы ни один хук не
  сработал дважды. `npx claude-protocol init` работает как работал.
- **Хуки-надзиратели не вмешиваются в проектах без `.beads/`** — проверять им
  там нечего, а плагин, поставленный «на себя», загружается везде.
- **`bd` больше не ставится молча** — установщик показывает команду для вашей
  системы и ждёт согласия; `--install-beads` отвечает «да» заранее. Потом
  проверяет, что система действительно видит `bd`, предупреждает о версии ниже
  1.1.0 и больше не создаёт руками пустую `.beads/`, когда `bd init` не
  отработал.
- **Вам сообщают о новой версии claude-protocol** — раз в неделю при старте
  сессии, из процесса с ограничением времени, с молчанием при любой неудаче.
- **Мелкие находки чинятся, а не заводятся задачами** — в `beads-workflow.md`
  умолчание было «заводи задачу на всё, на что наткнулся»; теперь по умолчанию
  чинишь в той же ветке, а задача только для того, что не помещается в текущую
  работу.

### v3.7.0 (2026-09-03)

- **Обновление спрашивает, а не оставляет домашнее задание** — по каждому
  правленому файлу, который мы тоже изменили, задаётся вопрос, с показом
  различий по запросу; `K` и `T` отвечают за все оставшиеся. Проигравшая версия
  сохраняется в `.claude/.upgrades/`.
- **Спрашиваем только там, где есть кому ответить** — нужен терминал и на
  входе, и на выходе. Пакетные запуски, сборка на сервере и работа агента
  сохраняют прежнее молчаливое поведение вместо ожидания ответа, которого не
  будет. `--keep-mine` — пара к `--force`.
- **`--dry-run` писал файлы** — флаг доходил только до шага очистки, поэтому
  предпросмотр, который README советует делать первым, менял тот самый проект,
  который показывал.

### v3.6.0 (2026-09-03)

- **Команды хуков перестали использовать относительные пути** — процесс хука
  наследует рабочий каталог последнего вызова Bash, поэтому
  `node .claude/hooks/x.cjs` молча переставал находиться, как только работа
  уходила в подкаталог или рабочую копию. Теперь корень проекта определяется
  внутри Node, а обновление переписывает устаревшие команды вместо добавления
  дубликатов.
- **Пять хуков стали тремя** — `enforce-branch-before-edit` и
  `nudge-claude-md-update` убраны, обновление вычищает их из существующих
  установок. `bash-guard` теперь проверяет каждую команду в цепочке:
  `cd sub && git commit --no-verify` раньше проскакивал.
- **Новое правило `pre-code-workflow.md`** на обоих языках плюс
  `repository-scope.md`. Сырой `git worktree add` заблокирован — он создаёт
  теневую `.beads/`.

### v3.5.0 (2026-05-27)

- **Новое правило `communication-style.md`** — простые слова вместо жаргона, в
  обоих языковых наборах.

### v3.4.0 (2026-05-15)

- **Новое правило `debugging-standard.md`** — триггер: та же ошибка пережила
  осознанную попытку исправить, значит хватит повторять, нужен другой подход.

### v3.3.0 (2026-04-22)

- **Механизм upgrade** — новая команда `npx claude-protocol upgrade` с
  флагами `--dry-run` и `--all <parent>` для пакетного обновления

- **Совместимость с bd 1.0.2** — репозиторий bd переехал на gastownhall;

- **Защита от path traversal** — upgrade никогда не пишет и не удаляет

Убрали всё, что не улучшает результат. Добавили всё, что улучшает.

**Убрано:**

- Генерация Tech Supervisor по стеку — 500+ строк контекста на каждый, Claude и так знает эти технологии

## Как работает

### Что устанавливается

```
.claude/
  agents/
    code-reviewer.md        # Adversarial 3-фазный ревью
    merge-supervisor.md     # Протокол разрешения конфликтов
  hooks/                    # 3 Node.js enforcement-хука, общая библиотека
                            # и запускаемая ими проверка обновлений
  rules/
    beads-workflow.md       # Жизненный цикл задач, справочник bd
    pre-code-workflow.md    # Три ворот перед любой правкой
    implementation-standard.md
    logging-standard.md
    tdd-workflow.md
    resilience-standard.md
  skills/
    project-discovery/      # Извлечение конвенций проекта
  settings.json             # Конфигурация хуков
  .manifest.json            # Хеши файлов для безопасных обновлений
CLAUDE.md                   # Инструкции оркестратора
.beads/                     # База задач + база знаний
```

Это установка через `npx`. При установке плагином в проект попадают только
`rules/`, `.manifest.json`, `CLAUDE.md` и `.beads/` — хуки, агенты и навык
остаются в плагине, благодаря чему и обновляются сами.

### Безопасно для существующих проектов — и для обновлений

Первая установка и переустановка используют одну команду: `npx claude-protocol init`.

- **Хуки** — всегда обновляются до последней версии (enforcement-код). Заменяются только наши файлы; свой хук остаётся нетронутым.
- **Правила, агенты и навык project-discovery** — обновляются, только если вы их не меняли. По правленому файлу задаётся вопрос; невыбранная версия ложится в `.claude/.upgrades/`. Ваши собственные файлы внутри каталога навыка не трогаются вообще.
- **CLAUDE.md** — наш только блок между метками `<!-- claude-protocol:begin -->` и `<!-- claude-protocol:end -->`, обновляется он один. Описание проекта, стек и текущее состояние не трогаются.
- **settings.json** — хуки мержатся по типу события. Ваши существующие хуки остаются.
- **.gitignore** — недостающие записи дописываются. Ничего не удаляется.

`--force` берёт нашу версию каждого файла. Правила, агенты, навык и блок в CLAUDE.md сначала копируются в `.claude/.upgrades/<путь>.mine`, причём прежняя копия не затирается, так что остаётся каждая заменённая версия. Хуки заменяются без копии — это enforcement-код, он и так перезаписывается при каждом запуске.

### Что происходит при старте сессии

Хук `session-start` говорит только то, чего не знает трекер задач. Сами задачи —
в работе, готовые, заблокированные, залежавшиеся — печатает `bd prime`, и
повторять их значит платить за второй такой же список.

Что он сообщает:

- **ACTION REQUIRED** — ветка влита, а её рабочая копия и задача всё ещё
  открыты; тут же команда, чтобы закрыть и то и другое
- **WARNING** — незакоммиченные правки в главном каталоге: подрядчики будут
  ответвляться от них
- **Open PRs** — ваши, ещё не разобранные
- **Устаревший `bd`** — версия ниже той, на которую опираются правила, с
  командой обновления
- **Новая версия claude-protocol** — проверяется не чаще раза в неделю,
  в отдельном процессе с ограничением времени, и молчит при любой неудаче

Сообщать нечего — не печатается ничего.

### Исследование проекта

После установки выполните `/project-discovery` в Claude Code. Команда сканирует кодовую базу и записывает `.claude/rules/project-conventions.md`:

- Обнаруженные технологии и фреймворки
- Конвенции именования и паттерны
- Настройка тестирования и команды
- Анти-паттерны специфичные для проекта

Файл автоматически загружается в контекст каждого агента. Генерация супервайзеров по стеку не нужна.

## Установка

### Требования

- Python 3.11+
- Node.js 20+
- git
- [beads CLI](https://github.com/gastownhall/beads#-installation) (`bd`)
  версии 1.1.0 или новее

### Установить

```bash
npx claude-protocol init --lang ru
```

Перезапустите Claude Code. Выполните `/project-discovery`.

**Если `bd` не установлен**, установщик покажет команду для вашей системы и
спросит согласия — глобальная программа на вашей машине это ваше решение.
Запуск, в котором некому ответить (сборка на сервере, пакетное обновление,
работа агента), не ставит ничего и просто печатает команду; флаг
`--install-beads` отвечает «да» заранее. Если программа установилась, но
система её не видит, установка останавливается: каталог установки не попал в
PATH этой оболочки — откройте новый терминал и повторите.

**Если `bd` старее 1.1.0**, установщик предупредит и продолжит, а хук старта
сессии повторит предупреждение один раз за сессию. Сами мы ничего не обновляем:
правила опираются на `bd memories`, `bd remember`, `bd worktree` и `bd prime`, а
старый `bd` отказывает по одной команде за раз, ничего не объясняя.

### Установка плагином

То же самое, но через собственную систему плагинов Claude Code. Плагин несёт
хуки, агентов и навык project-discovery и сам их обновляет. Чего плагин нести
не умеет — это половина, которая обязана лежать в проекте: база beads,
`.claude/rules/*.md` и блок в `CLAUDE.md`. Её раскладывает одна команда.

```
/plugin marketplace add weselow/claude-protocol
/plugin install claude-protocol@claude-protocol
/claude-protocol:init
```

Область установки выбирается при установке: **своя** — во всех проектах,
**проектная** — общая для всех участников репозитория через
`.claude/settings.json`, **локальная** — только этот репозиторий и только вы.
В проектах без `.beads/` хуки не вмешиваются, поэтому установка «на себя» не
станет проверять ваши посторонние репозитории.

**Автообновление по умолчанию выключено** — так у Claude Code устроены все
сторонние каталоги. Плагин останется на той версии, с которой поставлен, пока
вы не включите обновление: `/plugin` → **Marketplaces** → **claude-protocol** →
**Enable auto-update**. Независимо от этого хук старта сессии раз в неделю
скажет, что вышла новая версия.

**Уже стоит установка через `npx`?** После включения плагина выполните
`/claude-protocol:init`. Хуки складываются из всех источников, поэтому копии в
`.claude/hooks/` сработают вместе с плагинными и каждая проверка выполнится
дважды. Команда убирает копии, которые ставила сама, снимает их подключение в
`settings.json` и перечисляет снятое; копии удалённого ложатся в
`.claude/.upgrades/`. То, что вы добавили сами, не трогается.

### Опции

| Флаг | Описание |
|------|----------|
| `--project-dir PATH` | Целевая директория (по умолчанию: текущая) |
| `--project-name NAME` | Имя проекта для CLAUDE.md (автоопределяется из package.json / pyproject.toml / Cargo.toml / go.mod) |
| `--no-rules` | Пропустить dev-правила (implementation, logging, TDD, resilience) |
| `--lang en\|ru` | Язык dev-правил и `CLAUDE.md` (по умолчанию: en) |
| `--force` | Взять нашу версию каждого файла, без вопросов (твоя ложится в `.claude/.upgrades/`) |
| `--keep-mine` | Оставить твою версию каждого правленого файла, без вопросов |
| `--install-beads` | Поставить beads CLI без вопросов (по умолчанию спрашиваем, а когда ответить некому — не ставим ничего) |
| `--project-only` | Поставить только то, что плагин нести не умеет — beads, правила, CLAUDE.md, — а хуки, агентов и навык отдать плагину. Именно это выполняет `/claude-protocol:init` |

### Локальная разработка (до публикации в npm)

```bash
cd /path/to/claude-protocol && npm link
npx claude-protocol init --lang ru  # работает в любом проекте
```

## Upgrade

Существующие проекты обновляются безопасно: чистятся только артефакты самого
claude-protocol, и всё удаляемое сначала копируется в резерв.

Если файл правил и ты, и мы — обновление спросит по каждому: показать
различия, взять наш, оставить свой, либо ответить сразу за все оставшиеся
(`K` / `T`). Та версия, которую не выбрали, ложится рядом в
`.claude/.upgrades/`, поэтому написанное тобой не пропадает никогда. Там, где
отвечать некому — пакетное обновление, CI, запуск из агента, — твои файлы
остаются, наши кладутся рядом. Флаги `--force` и `--keep-mine` отвечают за все
файлы сразу.

**С `CLAUDE.md` иначе: файл твой, наш в нём только обрамлённый блок.** Всё
между `<!-- claude-protocol:begin -->` и `<!-- claude-protocol:end -->`
заменяется при обновлении; описание проекта, стек и текущее состояние вокруг
меток не читаются и не переписываются. Проект, установленный до появления
меток, спросят один раз — с показом различий, — обрамить ли блок, который в
нём уже есть. Откажешься — не изменится ничего: текущий шаблон ляжет в
`.claude/.upgrades/CLAUDE.md`, как и раньше.

### Предпросмотр (рекомендуется сначала)

```bash
npx claude-protocol@latest upgrade --dry-run
```

Печатает точный список файлов, директорий и записей settings-хуков, которые
будут изменены, и не пишет ничего — каждая строка предпросмотра помечена
`[DRY-RUN]`.

### Применить

```bash
npx claude-protocol@latest upgrade
```

Запускает init-сценарий, затем удаляет устаревшие артефакты. Каждое
удаление бэкапится в `.claude/.upgrades/<UTC-timestamp>/` — можно
откатиться, скопировав файлы обратно.

### Пакетно (несколько проектов)

```bash
npx claude-protocol@latest upgrade --all /path/to/parent
```

Проходит по всем прямым подпапкам parent-директории, в которых есть
`.beads/`, и обновляет каждую. Комбинируйте с `--dry-run`, чтобы сначала
проверить, что будет сделано.

### Rollback

Директория бэкапа `.claude/.upgrades/<timestamp>/obsolete/` повторяет
структуру проекта. Скопируйте нужные файлы обратно на место. Ничего не
удаляется безвозвратно.

## Workflow

### Каждая задача проходит через beads

```
План → Size check → Создать beads → bd ready → Dispatch → Worktree → PR → Merge → Close
```

**Size check** выполняется автоматически перед созданием beads:
- Больше 3 файлов или несколько доменов (DB + API + frontend) → epic с children
- Больше 50 строк по оценке → рассмотреть декомпозицию
- Иначе → один bead

Один bead = один worktree = один PR = один ревьюируемый diff.

### Параллельная работа

```bash
bd dep add TASK-2 TASK-1    # TASK-2 заблокирован TASK-1
bd close TASK-1              # TASK-2 становится ready
bd ready                     # показывает все незаблокированные задачи
```

Оркестратор диспатчит все ready-задачи параллельно через `Task()`.

### Quick fix

Для изменений до 10 строк на feature branch. На main жёстко заблокировано хуками.

```bash
git checkout -b fix-typo     # обязательно не main
# edit → хук запрашивает подтверждение → commit
```

### Верификация завершения

Субагенты блокируются от завершения если:
- Нет секции `Checklist:` со всеми отмеченными `[x]` пунктами
- Статус bead не `inreview`
- Код не закоммичен и не запушен
- Нет комментария к bead
- Ответ превышает лимиты (25 строк / 1200 символов)

## Хуки

| Хук | Событие | Что делает |
|-----|---------|------------|
| bash-guard | PreToolUse (Bash) | Блокирует `--no-verify` и сырой `git worktree add`. Требует описание для `bd create`. Проверяет закрытие epic (все дети закрыты, PR влит). Проверяется каждая команда в цепочке, а не только первая. |
| validate-completion | SubagentStop | Проверяет рабочую копию, отправку ветки, статус, чеклист, комментарий, многословность. |
| session-start | SessionStart | Незакоммиченное в главном каталоге, рабочие копии влитых веток, открытые PR, устаревший `bd`, новая версия claude-protocol. Список задач оставлен `bd prime`. |
| update-check | — | Не хук: вспомогательный файл, который запускает `session-start`, чтобы у проверки версии было своё ограничение времени. Ответ кешируется на неделю, при любой неудаче — молчание. |
| hook-utils | — | Общая библиотека: определение корня проекта, разбор команд, deny/ask/block, execCommand. |

**В проекте без `.beads/` хуки-надзиратели не вмешиваются.** Проверять им там
нечего, а запрещать `--no-verify` в репозитории, который ни о чём таком не
просил, — не их дело. Это важно для плагина, поставленного «на себя»: он
загружается в каждом открытом проекте.

При установке из npm команды хуков находят `.claude/hooks/` через
`CLAUDE_PROJECT_DIR`, а не по относительному пути: процесс хука наследует
рабочий каталог последнего вызова Bash, поэтому относительный путь перестаёт
находиться, как только работа уходит в подкаталог — а Claude Code считает это
неблокирующей ошибкой, и хук молча отсутствует. При установке плагином Claude
Code находит их сам по `hooks/hooks.json` через `CLAUDE_PLUGIN_ROOT`, и в ваш
проект эта обвязка вообще не пишется.

## Dev-правила

Включены по умолчанию. Пропустить: `--no-rules`. На русском: `npx claude-protocol init --lang ru`.

| Правило | Что делает |
|---------|------------|
| pre-code-workflow | По триггеру: трое ворот перед тем, как трогать код — отправные точки и таблица понимания, «готовое или заново» с рисками вида «файл:строка», план на 7–15 пунктов с обязательным разделом «вне области работ». Принят план — дальше beads-workflow. |
| implementation-standard | Действует, когда уже пишешь код. Метрики (функция < 30 строк, класс < 200, nesting < 4). Правило 3-х альтернатив. Self-review с триггером `/simplify`. |
| communication-style | По триггеру: срабатывает перед каждым ответом. Простые слова вместо жаргона, объяснение термина при первом упоминании, числа вместо прилагательных. |
| debugging-standard | По триггеру: «та же ошибка пережила осознанную попытку исправить» → перестать повторять, искать в памяти, читать исходник, потом три альтернативы. |
| logging-standard | На основе триггеров: "создаёшь API endpoint → добавь логирование". Покрывает внешние вызовы, платежи, авторизацию, фоновые задачи. Sentry + Seq. |
| tdd-workflow | На основе триггеров: "новая функция → сначала тест". Цикл RED → GREEN → REFACTOR. Чёткие исключения (конфиги, DTO, миграции). |
| resilience-standard | На основе триггеров: "вызываешь внешний API → что если таймаут/5xx?". Покрывает БД, платежи, файлы, фоновые задачи. Стратегии: retry, fallback, circuit breaker, compensation. |

## FAQ

**В: `bd init` зависает при установке.**
О: Dolt-сервер не запущен. Bootstrap создаёт `.beads/` вручную через 15 секунд. Запустите `bd init` позже когда Dolt будет доступен, или используйте SQLite-бэкенд.

**В: Хуки не работают после установки.**
О: Перезапустите Claude Code. Хуки загружаются из `settings.json` при запуске.

**В: Claude выдумывает команды типа `bd export`.**
О: В `beads-workflow.md` есть полная таблица команд. Если Claude всё равно выдумывает — проверьте что `.claude/rules/` существует.

**В: Что будет, если запустить `init` повторно после обновления claude-protocol?**
О: По каждому правленому правилу, агенту и файлу навыка зададут вопрос, с показом различий по запросу; невыбранная версия ложится в `.claude/.upgrades/`. Хуки обновляются всегда. В `CLAUDE.md` обновляется только наш обрамлённый блок — остальное остаётся твоим. Флаги `--force` и `--keep-mine` отвечают за всё сразу.

**В: Можно использовать без Dolt?**
О: Да. Beads по умолчанию работает с SQLite. Dolt добавляет версионную историю и ветвление для базы задач.
