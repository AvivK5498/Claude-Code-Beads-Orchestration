# 2026-09-05 — установка через маркетплейс: гибрид с npx

Система училась ставиться вторым способом — плагином Claude Code. Плагин несёт
исполняемую часть (хуки, агентов, навык), команда плагина раскладывает
проектную (beads, правила, `CLAUDE.md`). Установка через `npx` осталась как
была.

## Главное решение: ничего не переносили

Первая мысль была перенести `templates/hooks`, `templates/agents` и
`templates/skills` в отдельный каталог плагина. Не понадобилось: манифест
плагина умеет указывать на любые каталоги внутри репозитория. Образец нашёлся
среди установленных плагинов — `impeccable` объявляет себя как `"source": "./"`
и берёт навыки из `./.claude/skills`. У нас так же: корень репозитория
одновременно маркетплейс и плагин, `plugin.json` указывает на `./templates/...`.

Выигрыш — одна копия каждого файла. Две копии хука разъехались бы на первой же
правке.

## Что пришлось узнать по ходу

- **`claude plugin validate` не принимает каталог для `agents`** — только
  список файлов. Значит новый агент надо вписывать в манифест руками, иначе он
  поедет через `npx` и не поедет через плагин. Закрыто тестом
  `test_the_manifest_lists_every_agent_we_ship`.
- **`_cleanup_file` ждёт путь от корня проекта, а не ключ манифеста.** Ключ
  манифеста это `hooks/x.cjs`, а файл лежит в `.claude/hooks/x.cjs`. Передали
  ключ — файл не нашёлся, а запись из манифеста при этом стёрлась. Это
  единственная ошибка, которую тесты поймали не сразу: удаление «прошло»
  молча.
- **Три тестовые заглушки `copy_rules_and_skills`** имели жёсткую подпись и
  сломались о новый параметр. По правилу проекта неполный мок это ошибка, а не
  экономия, — расширили.

## Что проверять первым, если сломается

- **Хуки срабатывают дважды** — значит у проекта остались и копии в
  `.claude/hooks/`, и плагин. Лечится `/claude-protocol:init`. Если команда
  ничего не сняла — смотреть `manifest["files"]`: снимается только то, что
  числится в манифесте.
- **Плагин вмешивается в посторонний проект** — проверить, что в
  `bash-guard.cjs` и `validate-completion.cjs` жив ранний выход по `hasBeads()`.
- **Хук старта сессии отвечает про чужой каталог** — смотреть `getProjectDir()`:
  подъём вверх от файла хука разрешён только для копии, установленной в
  проекте. Из плагина этот подъём приводит в сам плагин, у которого есть и своя
  `.claude/`, и своя `.beads/`.
- **Медленный старт сессии** — проверка обновлений живёт в отдельном процессе
  (`update-check.cjs`) с ограничением времени и недельным кешем в
  `${CLAUDE_PLUGIN_DATA}` либо `~/.claude/`. Любая неудача обязана быть
  беззвучной.
- **Выпуск не доехал до пользователей плагина** — версия обязана вырасти в трёх
  файлах сразу, иначе у них остаётся копия из кеша. Держит тест
  `test_one_version_in_three_places`.

## Что осознанно не тронуто

- `bootstrap.py` и `templates/` остались на своих местах.
- Подача плагина в общий каталог сообщества — отдельное решение, после того как
  свой заработает.
- Русский `CLAUDE.md` — отдельная задача.
- Серверы MCP и LSP, оформление, мониторы — плагин их умеет, нам не нужны.
- Способ установки по умолчанию в README остался прежним: сначала `npx`.

## Чего не проверяли

Живую установку плагина на этой машине не делали намеренно: `/plugin
marketplace add ./` меняет настройки плагинов пользователя и включил бы наши
хуки поверх уже установленных в этом же репозитории — то самое двойное
срабатывание, только у себя. Это остаётся первым шагом ручной проверки после
слияния, на чистом проекте.
