# 2026-09-03 — пути к хукам: с относительных на определяемые из корня проекта

## Что сделано

Команды всех шести хуков перестали использовать относительный путь
(`node .claude/hooks/bash-guard.cjs`). Теперь команда — обёртка `node -e`,
которая сама находит корень проекта: сначала `CLAUDE_PROJECT_DIR`, затем
`git rev-parse --show-toplevel`, затем текущий каталог. Имя файла хука
передаётся обёртке аргументом.

Изменены:

- `templates/settings.json` — шесть команд в новой форме. Это единственный
  источник правды: `bootstrap.py` строки команд не хранит, а читает их отсюда.
- `bootstrap.py` — раздел «HOOK COMMAND PATHS»: `canonical_hook_commands()`
  читает шаблон, `migrate_hook_commands()` переписывает устаревшие команды,
  `merge_hooks()` заменил самодельное слияние в `copy_settings_and_claude_md`,
  `migrate_local_settings_hooks()` делает то же с личным файлом настроек.
  В список `OBSOLETE_SETTINGS_HOOKS` добавлены два мёртвых `.sh`-хука от
  форка до v3.
- `templates/hooks/hook-utils.cjs` — `getProjectDir()` больше не полагается на
  текущий каталог (порядок: переменная окружения → `<файл>/../..` → каталог);
  `execCommand()` запускает `git`/`bd`/`gh` в корне проекта, а не там, где
  оказался процесс хука.
- `.claude/settings.json` самого проекта — прогнан через те же функции
  `bootstrap.py`, а не переписан руками. Заодно выкинуты два мёртвых
  `.sh`-хука, которые падали на каждом вызове.
- Тесты: 30 новых в `tests/test_bootstrap.py`, 6 в `tests/hooks/hook-utils.test.js`.

## Почему так

Процесс хука наследует рабочий каталог последнего вызова Bash, а не каталог
проекта (замерено). Как только агент уходит в подкаталог или в рабочую копию
git, Node не находит скрипт по относительному пути. Claude Code считает это
неблокирующей ошибкой: вызов инструмента проходит, а проверок хука просто нет,
и сигнала об этом нет — только строка в stderr, похожая на шум.

Короткая форма `node "$CLAUDE_PROJECT_DIR/.claude/hooks/x.cjs"`, которую
предлагает документация, отвергнута замером: раскрытие переменной — работа
оболочки, а на машинах без Git Bash команды хуков идут через PowerShell, где
`$CLAUDE_PROJECT_DIR` — неопределённая переменная. Там форма падает даже из
корня проекта. Обёртка читает переменную внутри Node и потому не зависит от
оболочки — проверено в Git Bash, PowerShell и cmd.

Отдельная причина переписывать, а не добавлять: старое слияние настроек
отличало записи по строке команды. Новая строка отличается от старой, поэтому
обновление добавило бы вторую запись рядом с первой — сломанный хук продолжал
бы срабатывать вместе с исправленным.

## Что проверять первым при поломке

1. Хук вообще не запускается. В обход разрешений (`bypassPermissions`) запрет
   превращается в предупреждение, поэтому проверять живость хука запрещённой
   командой бесполезно. Проверять побочным следом: положить в
   `.claude/hooks/_probe.cjs` запись в файл, прописать его той же формой
   команды в `.claude/settings.local.json`, вызвать любой Bash, посмотреть файл.
   Настройки перечитываются внутри сессии — перезапуск не нужен (замерено).
2. `[claude-protocol] hook not found: <путь>` в stderr — корень проекта
   определился, а файла хука там нет. Это не поломка обёртки, а незавершённая
   установка: сверить `.claude/hooks/` со списком из `templates/settings.json`.
3. Обновление создало дубли записей — смотреть `merge_hooks()` и `_entry_key()`
   в `bootstrap.py`. Ключ записи — пара «сопоставитель + команда»: `Edit` и
   `Write` несут одну и ту же команду, и различие по одной команде теряет одну
   из двух записей.
4. `git`/`bd`/`gh` внутри хука отвечают не про тот каталог — смотреть
   `execCommand()` в `hook-utils.cjs`, там задан `cwd: getProjectDir()`.

## Что осознанно не тронуто

- `enforce-branch-before-edit.cjs`, строка 36: `containsPathSegment(process.cwd(),
  '.worktrees')` — если процесс хука оказался внутри рабочей копии, правка
  разрешается любая, включая правку главного репозитория на `main`. Это дыра
  в защите того же происхождения, но её закрытие меняет поведение защиты,
  а не путь. Оформлено отдельной задачей.
- Таблица хуков в `README.md` перечисляет `memory-capture` и `recall`, удалённые
  в v3.3.0. Расхождение документации возникло раньше, к путям не относится.
- `README.md`, ответ в разделе вопросов: «хуки загружаются при старте, нужен
  перезапуск». Замер показал, что настройки перечитываются внутри сессии.
  Совет остался верным по сути, формулировка неточна — не правил.
- Версия в `package.json` и выпуск — не поднимал, это решение пользователя.
