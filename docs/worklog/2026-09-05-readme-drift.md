# 2026-09-05 — README догнал код

Три блока в обоих README описывали программу, которой уже нет. Нашлось при
вопросе «а README ты доработал?» после работы над плагином — я обновил там
только раздел установки.

## Что разошлось и насколько

**«Что происходит при старте сессии»** отстал сильнее всех. Он перечислял
список задач — в работе, готовые, заблокированные, залежавшиеся, — который из
хука убрали ещё в версии 3.6.0: его печатает `bd prime`, и второй такой же
список стоил бы контекста впустую. И «Recent Knowledge — последние 5
LEARNED-записей» из базы знаний, удалённой в 3.3.0. То есть раздел был неверен
четыре выпуска подряд.

**Таблица хуков** не знала про `update-check.cjs` и про то, что в плагине хуки
приходят через `CLAUDE_PLUGIN_ROOT`, а в проектах без `.beads/` не вмешиваются.

**«Что изменилось в v3»** обрывался на 3.3.0. Дописал 3.4.0, 3.5.0, 3.6.0,
3.7.0 и раздел «Не выпущено» с пятью изменениями после 3.7.0.

## Почему отстало и что с этим сделано

Ни одно правило не говорило, что раздел истории надо пополнять. Добавил пункт
в `release-process.md`: при выпуске содержимое «Не выпущено» переезжает в
`### v3.x.x (дата)` в обоих README, а сверху заводится новый пустой раздел.
Это единственное, что удержит его от повторного отставания, — тестом такое не
проверишь.

## Что проверять первым, если сломается

- Раздел про старт сессии сверяется с `templates/hooks/session-start.cjs`:
  список того, что он собирает, — это функции `collect*` в нём.
- Таблица хуков сверяется с `templates/settings.json` (что зарегистрировано) и
  `hooks/hooks.json` (то же самое для плагина). `update-check.cjs` в обоих
  отсутствует намеренно — его запускает `session-start`, а не Claude Code.
- Даты выпусков брались из `git log -1 --format=%ad --date=short <тег>`.

## Что осознанно не тронуто

- Разделы «Убрано / Добавлено / Изменено» под v3.3.0 — они про v3 целиком,
  а не про конкретный выпуск.
- Тексты правил и код — правка только документная.
- Русский `CLAUDE.md` — отдельная задача.
