# 2026-09-07 — хуки даёт один источник

Началось с сообщения при загрузке плагина: `Duplicate hooks file detected`.
Причина оказалась в одной строке `.claude-plugin/plugin.json` — в манифесте был
объявлен `./hooks/hooks.json`, тот самый файл, который Claude Code подхватывает
сам. Поле `hooks` в манифесте предназначено только для *дополнительных* файлов
хуков; стандартный грузится всегда. Хуки при этом работали — побеждала
автоматическая загрузка, а падала объявленная, — но сообщение видел каждый, кто
ставил плагин.

Разбор потянул за собой большее: плагин и `npx claude-protocol init` подключают
одни и те же три хука, а Claude Code складывает хуки из всех источников. Проект
с двумя установками выполнял каждую проверку дважды. Передача хуков плагину
была написана и работала, но запускалась только вручную, командой
`/claude-protocol:init`, — то есть срабатывала лишь у того, кто о ней помнил.

## Что сделано

Три слоя, все опираются на один признак — реестр Claude Code
`plugins/installed_plugins.json` в `CLAUDE_CONFIG_DIR` или `~/.claude`:

- `runHook` в `templates/hooks/hook-utils.cjs` завершает копию из проекта, если
  плагин действует. Одно место на все хуки, а не по проверке в каждом.
- `bootstrap_project` переводит полную установку в `--project-only`, когда
  плагин уже стоит, — и там же отрабатывает передача, так что старая установка
  вычищается в тот же проход.
- `session-start.cjs` из плагина сообщает, что остатки прежней установки на
  месте, и называет команду, которая их уберёт. Без этой строки молчаливый
  отход копии необъясним.

## Что проверять первым, если сломается

- **Хуки перестали срабатывать вообще.** Первым делом `pluginActiveHere` в
  `templates/hooks/hook-utils.cjs`: она вернула «плагин действует» там, где он
  на самом деле не работает. Проверить руками содержимое
  `~/.claude/plugins/installed_plugins.json` — поля `scope` и `projectPath` — и
  `enabledPlugins` в трёх файлах настроек (пользовательском и двух проектных).
- **Установка через `npx` перестала ставить хуки.** То же самое, но со стороны
  `plugin_active_for` в `bootstrap.py`.
- **Ответы двух сторон разошлись.** `TestBothSidesReadTheRegistryTheSameWay`
  задаёт обеим одинаковые вопросы; правило живёт в двух языках и разъезжается
  молча, как разъехался бы `BD_MIN_VERSION` без своей проверки.
- Сравнение путей: относительный путь в реестре не совпадает ни с чем
  намеренно, а символические ссылки и короткие имена Windows разворачиваются
  (`realpath` в Node, `resolve()` в Python).

Общий принцип во всех трёх местах: любая неудача чтения означает «плагин не
действует» — ставим и запускаем как раньше. Реестр, который мы не смогли
разобрать, не повод лишать человека хуков; обратная ошибка стоит одного лишнего
хука, а эта — тишины вместо всех проверок сразу.

## Что осознанно не тронуто

- Поле `commands` в манифесте указывает на `./commands/init.md`, а `commands/` —
  стандартный каталог. Ошибки не даёт: объявление заменяет автопоиск, файл там
  один и тот же. Но второй файл-команду придётся вписывать в манифест руками.
- Временные каталоги тесты за собой не убирают — так во всём наборе, менять это
  внутри одной задачи смысла нет.
- Отход копии из проекта происходит молча, без вывода в свой поток. Говорит об
  этом только плагин, один раз за сессию.
