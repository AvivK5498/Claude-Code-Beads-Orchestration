**Удалены два хука.**

- `enforce-branch-before-edit` (PreToolUse на Edit/Write) — запрещал правку на
  `main` и спрашивал подтверждение на остальных ветках. Решение пользователя:

- `nudge-claude-md-update` (PreCompact) — уговаривал дописать «Current State» в

  состояние туда, откуда его сознательно убрали.

**`session-start` урезан.** Убраны четыре вызова `bd` (список задач в работе,
готовых, заблокированных, застоявшихся) — это ровно то, что печатает `bd prime`,
который bd ставит на старт сессии сам. Осталось то, чего трекер задач не знает:
незакоммиченное в главном каталоге, рабочие копии влитых веток, открытые PR.
Заодно убран вызов `bd --version`: после удаления списков хук к bd не обращается,
и отказываться показывать состояние репозитория из-за отсутствия bd было бы
неверно. Файл переписан по функции на раздел — главная функция стала 12 строк
вместо 120.

**`bash-guard` — закрыта дыра с первым словом.** Проверялось только первое слово
команды, поэтому `cd куда-то && git commit --no-verify` проходил насквозь.
Добавлен `splitCommandSegments()` в `hook-utils.cjs`: команда режется по `&&`,
`||`, `;`, `|`, `&` и переводам строки, кавычки не режутся. Каждая команда
цепочки проверяется отдельно. Побочно исчезли два ложных срабатывания:
`echo "--no-verify"` и `npm test --no-verify` больше не запрещаются, потому что
флаг теперь должен принадлежать именно команде `git`.

**Обновления вокруг.** `templates/settings.json` — три записи вместо шести.
`bootstrap.py` — оба удалённых хука внесены в `OBSOLETE_FILES` и
`OBSOLETE_SETTINGS_HOOKS`, чтобы обновление вычистило их из чужих проектов
(файл удаляется с резервной копией, запись из настроек — тоже). README на двух
языках: таблица хуков, счётчики «8 хуков», описание дашборда старта сессии.
`docs/decisions-*.md` — пример «ограничение вместо инструкции» переписан на
живой хук.

## Почему так, а не иначе

Удаление хука — не только удаление файла. Если просто убрать его из шаблона,
у всех, кто уже поставил пакет, запись в `settings.json` останется, файл
останется, и каждый вызов Edit будет тратиться на запуск отсутствующего скрипта.
Поэтому удаление идёт через те же списки очистки, что и прошлые удаления, и
проверено на настоящем файле настроек этого проекта.

Разделитель команд намеренно **не** режет подстановки (`$(...)` и обратные
кавычки). Резать их — значит отрывать флаги от команды, к которой они относятся,
и терять больше проверок, чем приобретать. Ограничение описано в комментарии
к функции.

## Что проверять первым при поломке

1. Хук не сработал на цепочке — проверить `splitCommandSegments()` в
   `hook-utils.cjs` тестами: `npx vitest run tests/hooks/hook-utils.test.js`.
   Там семь случаев, включая кавычки и фоновый `&`.
2. Обновление чужого проекта оставило удалённый хук — смотреть порядок в
   `bootstrap_project()`: `copy_settings_and_claude_md` идёт ДО
   `cleanup_obsolete`, и очистка работает только с флагом `--upgrade`.
3. `session-start` молчит — так и задумано: если нечего сказать, хук выходит
   без вывода. Раньше он всегда печатал раздел «Task Status».

## Что осознанно не тронуто

- `validate-completion` — оставлен как есть по решению пользователя. Он
  разбирает внутренний формат стенограмм Claude Code (`agentId`,
  `parentToolUseID`) и при смене формата тихо перестанет проверять. Это стоит
  иметь в виду, но переписывать сейчас не под что.
- Предупреждение Node DEP0190 (`execFileSync` с `shell: true` и массивом
  аргументов) — печатается в stderr при каждом запуске хука, который зовёт
  `git`/`bd`/`gh`. Косметика сегодня, ошибка в будущей версии Node. Отдельная
  задача.
- `docs/decisions-*.md`, строки 166 и 174 — описывают `recall.cjs` как текущее
  решение, хотя система памяти удалена в v3.3.0. Расхождение старое, не от этой
  правки. Отдельная задача.
- `CLAUDE.md` этого проекта — там же было указание запускать удалённый
  `node .beads/memory/recall.cjs`; заменено на `bd memories`. Файл в git не
  отслеживается (в `.gitignore`), так что правка локальная и в выпуск не идёт.
- Правила в `.claude/rules/` — следующий шаг работы. Важно: `beads-workflow.md`
  по-прежнему запрещает работу на `main`, а хук, который это принуждал, удалён.
  Теперь это только текст правила.
