# 2026-09-05 — репозиторий обновил сам себя до 3.8.1

В `.claude/` этого проекта стояла установка 3.2.1: манифест старого формата,
семь отслеживаемых файлов, среди них два хука, которых нет с 3.6.0. Обновление
до 3.8.1 через `npx claude-protocol@3.8.1 upgrade`.

## Почему это не опасно, хотя выглядит опасно

Проект — исходник самого claude-protocol, и `.claude/rules/` здесь не копия
шаблонов, а проектные правила под git: `repository-scope.md` и
`release-process.md` существуют только тут, остальные правлены. `CLAUDE.md`
тоже написан руками и меток управляемого блока не имеет.

Предпросмотр `--dry-run` показал ровно то, что нужно: одиннадцать файлов
(агенты, восемь правил, `CLAUDE.md`) помечены «yours kept», шаблонные версии
положены рядом в `.claude/.upgrades/` для сравнения. Перезаписываются только
пять хуков — а они в этом репозитории и так байт в байт равны `templates/hooks/`,
потому что здесь это одно и то же.

Итог в отслеживаемых файлах: ничего. `git status` чист.

## Найдено по дороге

Установщик дописал в `.gitignore` раздел `# Beads orchestration` с записью
`.claude/.upgrades/`, хотя строкой выше уже стояло `/.claude/.upgrades/`.
Причина — `bootstrap.py:1806-1809`: наличие записи проверяется как
`e not in lines and e.rstrip("/") not in lines`, ведущий слэш не учитывается,
а для git это одна и та же запись. Дубль откачен, заведена задача
`The-Claude-Protocol-f76`.

## Что проверять первым, если сломается

- **Хуки не срабатывают после обновления** — смотреть `.claude/settings.json`:
  команды должны разрешать корень проекта внутри Node, а не полагаться на
  текущий каталог. Проверка: `node --check .claude/hooks/*.cjs` и запуск
  `session-start.cjs` с `{"cwd": "<корень>"}` на входе — пустой вывод и код 0
  здесь норма, панель печатается только когда есть о чём сообщить.
- **Правило вдруг подменилось шаблонным** — значит файл совпал с записью в
  манифесте и обновление сочло его нетронутым. Прежняя версия лежит в
  `.claude/.upgrades/rules/<имя>.md`.
- **`bd doctor` ругается на устаревшие хуки git** (`pre-commit@1.0.2` при
  текущей 1.1.0) — это beads, а не claude-protocol; лечится
  `bd hooks install --force`.

## Что осознанно не тронуто

- Предупреждения `bd doctor` про `.beads/.gitignore` и хуки git — не наша
  установка, отдельная работа.
- `.claude/.upgrades/` с копиями шаблонных версий — оставлено как справочный
  материал, каталог под `.gitignore`.
