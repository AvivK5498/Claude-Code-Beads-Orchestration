# 2026-09-03 — правила: ворота перед кодом и чистка набора

Третья задача этого дня. Первые две — `2026-09-03-hook-paths.md` (пути к хукам)
и `2026-09-03-hook-revision.md` (состав хуков).

## Что сделано

**Новое правило `pre-code-workflow.md`** в обоих наборах (en, ru). Источник —
личный набор «ворот перед кодом», обкатанный в
глобальном файле пользователя с 27 августа. Переложен в формат остальных правил:
главное правило → триггер → шаги → запреты.

Две правки против оригинала:

- **Стык с beads.** Шаг 3 заканчивается фразой «план принят — дальше по
  `beads-workflow.md`». В оригинале дальше шёл текст, повторяющий раздел
  «After planning — size check» из beads-workflow. Теперь переход назван один раз.
- **Журнал работ разведён с задачами.** Добавлена таблица «куда что писать»:
  комментарии к задаче — ход работы (закрываются вместе с задачей); `bd remember`
  — урок для другого проекта; `docs/worklog/` — что проверять первым при поломке
  (находится грепом, когда задача давно закрыта). Без этого правило требовало бы
  писать одно и то же дважды, а проект стоит на «beads — единственный источник
  правды».

**`implementation-standard.md`** (обе версии). Убран раздел «Процесс с
пользователем» — его заменили ворота, осталась строка-отсылка. Убраны два
самоповтора внутри файла: «после каждого блока: линтинг → компиляция → тесты →
запуск» стояло и пунктом в «Key fundamentals», и отдельным разделом; «качество
важнее скорости» — так же. Раздел «Core Development Principles» из семи общих
утверждений заменён коротким разделом «Запреты» с конкретикой.

**Английский `communication-style.md` переписан.** Был английский текст,
предписывающий писать по-русски, со списком русских слов-маркеров: любой, кто
ставил пакет без `--lang ru`, получал правило отвечать на русском. Теперь это
правило про простой язык вообще — отвечать на языке пользователя, простое слово
вместо жаргона, объяснять термин при первом упоминании, числа вместо
прилагательных. Списки русских маркеров остались в русском наборе.

**`beads-workflow.md`** (обе версии). Три абзаца про особенности bd 1.0.2
(метки `none` / `local (no redirect)`, защита от `issues.jsonl`) свёрнуты в
четыре строки с отсылкой к `bd memories worktree`. Сам факт уже лежит в памяти
beads, а в правиле он занимал место в контексте каждой сессии у каждого
пользователя.

**Русский `beads-workflow.md` подключён.** Он существовал, но не ставился
никогда: `copy_rules_and_skills` брала английский файл всегда, а из
языкового набора этот файл исключался. 8 КБ мёртвого груза в пакете. Теперь
берётся перевод, если он есть. Перевод сохраняет строки `BEAD {BEAD_ID}
COMPLETE` и `Checklist:` — их дословно ищет `validate-completion.cjs`, и тест
это закрепляет.

**Тесты (10 новых).** Паритет наборов en/ru по именам файлов; в английском
наборе нет кириллицы (закрепляет исправленный дефект); в русском — есть;
`beads-workflow` в обоих наборах сохраняет строки отчёта; у каждого правила есть
триггер; ворота ссылаются на beads-workflow, а стандарт имплементации — на
ворота; общий размер набора меньше 20 тыс. символов.

## Второй заход: сжатие

Первая версия этой работы дала +2 058 символов постоянной нагрузки (en) — то
есть чистка окупила лишь около 40% новых ворот. По решению пользователя сжали
дальше.

**`beads-workflow.md`: 5 206 → 3 756 (−28%).** Главная находка — правило учило
командам bd, которые bd объясняет сам: `bd prime` печатает полный справочник при
старте каждой сессии. Всё, что пересказывало синтаксис (`--type` со списком
значений, «Verify: bd list», раскладка `bd create` по вариантам), убрано; вместо
этого одна строка «это правило про порядок работы, а не учебник по bd». Дальше:
четыре пункта «когда заводить задачу» сведены к двум предложениям (первый пункт
покрывал остальные), шесть пунктов дисциплины статусов — к одной строке
переходов, раздел «Discovered during work» слит с «когда заводить». Формат
отчёта о завершении не тронут — его дословно ищет хук.

**`templates/CLAUDE.md`: 2 738 → 2 044 (−25%).** «Расследуй до делегирования»
было сказано дважды — в «Your Identity» и отдельным разделом; осталось одно
место, с сохранением жёстких требований (не раздавать работу без чтения
исходника, не заводить задачу с расплывчатым описанием). Шаги 1–3 рецепта
«Standalone» (расследовать → обсудить → пользователь подтверждает) дословно
повторяли новые ворота — заменены отсылкой. Рецепты Epic и Quick Fix сжаты до
двух абзацев. Уникальное сохранено: форма вызова `Task(...)` и комментарий
`INVESTIGATION:` перед раздачей — их нет больше нигде.

## Что проверять первым при поломке

1. Субагент не может закрыть задачу, хук ругается на формат отчёта — проверить,
   не потерял ли перевод `beads-workflow.md` строки `BEAD {BEAD_ID} COMPLETE`
   или `Checklist:`. Тест `test_beads_workflow_keeps_the_report_format`.
2. Пользователь с `--lang ru` получил английские правила — смотреть выбор
   `beads_src` в `copy_rules_and_skills`: перевод берётся, только если файл
   существует в языковом каталоге.
3. Набор правил разъехался между языками — `test_both_sets_hold_the_same_files`.

## Что осознанно не тронуто

- **`logging-standard.md`** предписывает всем Sentry, Seq, pino, structlog,
  Serilog — инфраструктура одного человека в общей поставке. Решение
  пользователя: оставить как есть.
- **`CLAUDE.md` самого проекта** (не шаблон, а локальный файл в корне) несёт
  ту же двойную формулировку «расследуй до делегирования», что была в шаблоне.
  Файл в `.gitignore`, в выпуск не идёт, поэтому не трогал.
- **`docs/decisions-*.md`** — там остаётся описание удалённой системы памяти
  (задача `n3c`), к правилам отношения не имеет.
- Отложенная в `DECISIONS.md` идея вынести ворота в навык (сэкономила бы ~600
  символов постоянной нагрузки ценой того, что правило срабатывает, только когда
  про навык вспомнят). Для пакета, который ставят чужие люди, ненадёжно.
