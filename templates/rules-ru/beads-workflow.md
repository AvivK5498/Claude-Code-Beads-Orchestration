# Рабочий процесс Beads

## Beads = единый источник истины. Ничто не должно жить только у тебя в голове.

Контекст сжимается. Сессии перезапускаются. Задачи в beads остаются.

Это правило про порядок работы, а не учебник по bd: справочник команд печатает
`bd prime` при старте сессии, остальное — `bd <команда> --help`.

### Когда заводить задачу

Всё, что пользователь просит сделать, починить или изменить, и всё нетривиальное,
во что ты сам решил вникнуть. А также то, на что наткнулся попутно — ошибка,
технический долг, продолжение, которое сейчас не сделаешь:

```bash
bd create "Fix: [что]" -d "Найдено при работе над {ТЕКУЩАЯ_ЗАДАЧА}: [детали]"
```

Не чини по ходу, если это не мелочь: задача — то, что не даст забыть.

**Не задача:** быстрая правка, одобренная пользователем (<10 строк, не на main),
и исследование или обсуждение без правок кода.

### После планирования — оценка размера, потом задачи

План готов и подтверждён, ДО реализации:

- >3 файлов ИЛИ >1 области (база + API, бэкенд + фронтенд) → epic с детьми
  (`--type epic`, дети через `--parent` и `--deps`)
- «а потом», «после этого», несколько шагов в описании → несколько задач
- >50 строк по оценке → подумай о разбиении
- Иначе → одна задача

Ориентир: 1 задача = 1 PR = 1 обозримый дифф. Дальше `bd list` — убедиться, что
план теперь живёт в beads, а не только в контексте, и `bd ready` → раздача.

### Дисциплина статусов

`open` → `in_progress` при начале работы → комментарий `AWAITING REVIEW` при
сдаче, **статус остаётся `in_progress`** → пользователь закрывает после слияния PR.

Epic переходит в `in_progress` вместе с первым ребёнком и остаётся там, пока не
готовы все. Не оставляй задачу в `in_progress` между сессиями без причины.

## Начало задачи

1. Распарси BEAD_ID из dispatch-промпта
2. Создай рабочую копию (git worktree — отдельная рабочая папка одного
   репозитория), ОБЯЗАТЕЛЬНО через bd, не через сырой git (см. Запреты):
   ```bash
   bd worktree create .worktrees/bd-{BEAD_ID} --branch bd-{BEAD_ID}
   cd .worktrees/bd-{BEAD_ID}
   ```
   База у неё общая с главным репозиторием — надписи вроде `none` или
   `local (no redirect)` косметические, это не поломка. Что-то странное вокруг
   рабочих копий и bd — сначала `bd memories worktree`, потом разбирайся.
3. `bd update {BEAD_ID} --status in_progress` — и родительский epic тоже, если
   он ещё `open`
4. Прочти переданный контекст: `bd show {BEAD_ID}` и `bd comments {BEAD_ID}`

## Во время реализации

- Работай ТОЛЬКО в своей рабочей копии: `.worktrees/bd-{BEAD_ID}/`
- Коммить часто, с внятными сообщениями
- Пиши о ходе работы: `bd comments add {BEAD_ID} "Сделано X, делаю Y"`

## Завершение задачи

Всё, по порядку:

1. **Самопроверка:** перечитай описание через `bd show {BEAD_ID}` и сверься с
   каждым требованием. Чего-то нет — доделай сейчас, не пропускай.
2. `git add -A && git commit -m "..."`, затем `git push origin bd-{BEAD_ID}`
3. `bd comments add {BEAD_ID} "Completed: [итог]"`, затем второй комментарий
   `AWAITING REVIEW`. Статус оставь `in_progress` — закрывает пользователь.
4. Верни отчёт о завершении (чеклист ОБЯЗАТЕЛЕН — без него хук заблокирует):
   ```
   BEAD {BEAD_ID} COMPLETE
   Worktree: .worktrees/bd-{BEAD_ID}
   Checklist:
   - [x] требование 1 из описания
   - [x] требование 2 из описания
   Files: [только имена]
   Tests: pass
   Summary: [одно предложение]
   ```

## Запреты

- Работать прямо на ветке main
- Реализовывать без BEAD_ID
- Сливать свою же ветку (слияние через PR делает пользователь)
- Править файлы вне своей рабочей копии
- Сырой `git worktree add` — создаёт теневую копию `.beads/`, плодит процессы
  dolt и теряет данные задач. Только `bd worktree create`. Удалять через сырой
  `git worktree remove --force` + `git worktree prune` МОЖНО: `bd worktree
  remove` сломан на Windows (баг u51).
